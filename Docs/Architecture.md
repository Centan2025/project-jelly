# Project Jelly — Architecture Specification

## 1. Architectural Principles
- **Component-Based & Decoupled:** Gameplay physics, mass/volume calculation, gate evaluation, fragment conservation, and visual deformation are separated into focused components within `Jelly.Runtime`.
- **Data-Driven Configuration:** Movement parameters ([`JellyMovementConfig`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyMovementSystem.cs#L8-L30)), mass/morph parameters ([`JellyMassConfig`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyMassAndMorphSystem.cs#L7-L20)), and level layouts ([`JellyLevelDefinition`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyLevelSystem.cs#L94-L124)) live in `ScriptableObject` assets.
- **Single-Source Mass & Fragment Authority:** [`JellyMassModel`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyMassAndMorphSystem.cs#L23-L61) and [`JellyFragmentRegistry`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellySplitAndMergeSystem.cs#L52-L135) own the authoritative mass and active fragment states.
- **Physics Integrity:** Forces and torques are applied strictly inside `FixedUpdate` via [`JellyMotor`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyMovementSystem.cs#L244-L315). `RigidbodyInterpolation.Interpolate` and `CollisionDetectionMode.ContinuousDynamic` prevent high-speed tunneling and camera jitter.
- **Mobile Pooling:** Both split fragments ([`JellyFragmentPool`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellySplitAndMergeSystem.cs#L137-L169)) and particle effects ([`JellyFXPool`](file:///c:/Users/ASUS/.gemini/antigravity/scratch/JellyShift/Assets/Jelly/Runtime/JellyCameraVisualAndUISystem.cs#L95-L141)) use object pooling to avoid runtime GC spikes.
